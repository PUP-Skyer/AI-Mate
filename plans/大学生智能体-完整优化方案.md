## 一、项目概览

### 1.1 目标

将 react-ai-chat 子应用从"前端原型"升级为"可用的企业级 AI 创业助手"，打通 **前端交互 → 后端服务 → 数据库 → AI模型 → 知识库** 全链路，使四大 AI 角色（探路者、军师、工匠、管家）具备真实的业务能力。

### 1.2 技术栈

| 层级 | 技术选型 | 版本 |
|------|----------|------|
| 前端框架 | React + TypeScript | 19.2 / 5.x |
| 构建工具 | Vite | 6.x |
| UI组件库 | Ant Design | 6.3 |
| 状态管理 | Zustand + Immer | 5.0 / 11.1 |
| 微前端 | qiankun | 2.10 |
| 后端服务 | Node.js + Express | 20.x / 5.x |
| 数据库 | MySQL | 8.0+ |
| AI模型 | 智谱 GLM-4 + Coze | - |
| 流式传输 | Server-Sent Events (SSE) | - |
| 全文检索 | MySQL FULLTEXT + ngram parser | - |

### 1.3 四大AI角色

| 角色 | 代号 | 职责 | 核心功能 | 推荐模型 |
|------|------|------|----------|----------|
| 探路者AI | scout | 市场洞察 | 市场分析、竞品调研、趋势洞察、机会评估 | GLM-4 + Coze（搜索） |
| 军师AI | sage | 策略规划 | 策略对话、商业模式画布（含幕布式思维导图）、风险矩阵、融资规划 | GLM-4 |
| 工匠AI | maker | 作品生成 | 项目脚手架、PPT大纲、产品文档、原型描述、原型Demo展示（Web/APP/小程序/桌面端预览） | GLM-4 + Coze |
| 管家AI | butler | 项目管理 | 任务管理、进度跟踪、资源对接、团队协作 | GLM-4-Flash |

## 三、数据库设计总览

### 3.1 新增表清单

在现有 `users`、`sign_in_records`、`desk_pets`、`user_settings` 四张表基础上，新增以下五张核心业务表：

| 表名 | 用途 | 关键特性 |
|------|------|----------|
| `conversations` | 对话记录 | ENUM 角色（scout/sage/maker/butler）、状态管理、置顶 |
| `messages` | 消息记录 | 外键级联删除、JSON 元数据（模型名/响应时间/Token用量） |
| `ai_models` | 模型配置 | 唯一约束（provider+model_id）、JSON 配置、加密密钥 |
| `knowledge_base` | 知识库 | FULLTEXT INDEX with ngram parser（中文全文检索） |
| `demo_projects` | Demo作品展示 | 6级项目阶段枚举、OPC/OTC团队类型、JSON外部链接（GitHub/Gitee/抖音/B站/X/小红书） |

### 3.2 核心表结构

**conversations 对话表：**

```sql
CREATE TABLE IF NOT EXISTS conversations (
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  user_id INT UNSIGNED NOT NULL DEFAULT 1,
  project_id INT UNSIGNED DEFAULT NULL,
  ai_role ENUM('scout', 'sage', 'maker', 'butler') NOT NULL,
  title VARCHAR(200) NOT NULL DEFAULT '新对话',
  model_id INT UNSIGNED DEFAULT NULL,
  status ENUM('active', 'archived', 'deleted') DEFAULT 'active',
  summary TEXT,
  is_pinned TINYINT(1) DEFAULT 0,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX idx_user_role (user_id, ai_role),
  INDEX idx_status (status),
  INDEX idx_updated (updated_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

**messages 消息表：**

```sql
CREATE TABLE IF NOT EXISTS messages (
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  conversation_id INT UNSIGNED NOT NULL,
  role ENUM('user', 'assistant', 'system') NOT NULL,
  content TEXT NOT NULL,
  token_count INT UNSIGNED DEFAULT 0,
  metadata JSON COMMENT '模型名称、响应耗时、Token用量等',
  is_error TINYINT(1) DEFAULT 0,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (conversation_id) REFERENCES conversations(id) ON DELETE CASCADE,
  INDEX idx_conversation (conversation_id),
  INDEX idx_role (role),
  INDEX idx_created (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

**ai_models 模型配置表：**

```sql
CREATE TABLE IF NOT EXISTS ai_models (
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  provider ENUM('zhipu', 'coze', 'openai') NOT NULL,
  api_endpoint VARCHAR(500) NOT NULL,
  model_id VARCHAR(100) NOT NULL,
  api_key_enc TEXT NOT NULL COMMENT '加密后的API密钥',
  config JSON COMMENT 'temperature, max_tokens, top_p等',
  is_active TINYINT(1) DEFAULT 1,
  is_default TINYINT(1) DEFAULT 0,
  sort_order INT DEFAULT 0,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_provider_model (provider, model_id),
  INDEX idx_provider (provider),
  INDEX idx_active (is_active)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

**knowledge_base 知识库表：**

```sql
CREATE TABLE IF NOT EXISTS knowledge_base (
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,

```

### 3.4 实施要点

- 所有新表使用 `utf8mb4` + `utf8mb4_unicode_ci`，支持 emoji 和中文
- `messages.conversation_id` 外键设置 `ON DELETE CASCADE`，删除对话时消息自动删除
- `knowledge_base` 的 `FULLTEXT INDEX ... WITH PARSER ngram` 需要 MySQL 8.0+
- `demo_projects` 的 `links` 字段使用 JSON 类型存储 GitHub/Gitee/抖音/哔哩哔哩/X/小红书 等外部链接
- 建表语句使用 `CREATE TABLE IF NOT EXISTS`，默认数据插入有 count 检查，可安全重复执行
- `api_key_enc` 为占位符，实际部署时必须通过环境变量注入并加密存储


### 4.3 错误处理中间件

后端在所有路由之后注册两层中间件：

- **404 处理**：未匹配到路由时返回 `code=404`
- **全局错误处理**：捕获未处理异常，按错误类型分类响应：
  - `ER_NO_SUCH_TABLE` → 500（数据库未初始化）
  - `ER_DUP_ENTRY` → 409（唯一约束冲突）
  - `ER_NO_REFERENCED_ROW_2` → 400（外键约束失败）
  - `ECONNREFUSED` → 503（数据库连接失败）
  - `entity.parse.failed` → 400（JSON格式错误）

```javascript
// 使用 BOOLEAN MODE 精确匹配 + NATURAL LANGUAGE MODE 相关性排序
app.get('/api/knowledge-base/search', async (req, res) => {
  const pool = getPool();
  const { query: searchQuery, category, limit = '5' } = req.query;
  if (!searchQuery?.trim()) {
    return res.status(400).json(error('搜索关键词不能为空', 400));
  }

  const resultLimit = Math.min(20, Math.max(1, parseInt(limit, 10) || 5));
  let sql = `
    SELECT id, title, content, category, source, tags,
      MATCH(title, content) AGAINST(? IN NATURAL LANGUAGE MODE) AS relevance
    FROM knowledge_base
    WHERE is_published = 1
      AND MATCH(title, content) AGAINST(? IN BOOLEAN MODE)
  `;
  const params = [searchQuery, searchQuery];
  if (category) { sql += ' AND category = ?'; params.push(category); }
  sql += ' ORDER BY relevance DESC LIMIT ?';
  params.push(resultLimit);

  const [rows] = await pool.execute(sql, params);
  const results = rows.map(row => ({
    ...row,
    excerpt: row.content.length > 200 ? row.content.substring(0, 200) + '...' : row.content,
    relevance: Number(row.relevance),
  }));
  res.json(success({ query: searchQuery, total: results.length, results }));
});
```

**SSE 流式接口（后端）：**

```javascript
// POST /api/ai/chat/stream
// 使用 Server-Sent Events 实现流式输出
app.post('/api/ai/chat/stream', async (req, res) => {
  const { messages, system_prompt, model_id, temperature = 0.7, max_tokens = 4096 } = req.body;

  // 设置 SSE 响应头
  res.setHeader('Content-Type', 'text/event-stream');
  res.setHeader('Cache-Control', 'no-cache');
  res.setHeader('Connection', 'keep-alive');

  // 从数据库获取模型配置
  const pool = getPool();
  const [modelRows] = await pool.execute('SELECT * FROM ai_models WHERE id = ? AND is_active = 1', [model_id]);
  if (modelRows.length === 0) {
    res.write(`data: ${JSON.stringify({ error: '模型不存在或未启用' })}\n\n`);
    return res.end();
  }

  const model = modelRows[0];
  const apiKey = decryptApiKey(model.api_key_enc);

  // 调用智谱 GLM-4 流式接口
  const response = await fetch(model.api_endpoint, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', 'Authorization': `Bearer ${apiKey}` },
    body: JSON.stringify({
      model: model.model_id,
      messages: [{ role: 'system', content: system_prompt }, ...messages],
      temperature, max_tokens, stream: true,
    }),
  });

  // 转发 SSE 流
  const reader = response.body.getReader();
  const decoder = new TextDecoder();
  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    const chunk = decoder.decode(value);
    // 解析智谱返回的 SSE 数据并转发给前端
    const lines = chunk.split('\n').filter(l => l.startsWith('data: '));
    for (const line of lines) {
      const data = line.slice(6);
      if (data === '[DONE]') { res.write('data: [DONE]\n\n'); break; }
      try {
        const parsed = JSON.parse(data);
        const content = parsed.choices?.[0]?.delta?.content;
        if (content) res.write(`data: ${JSON.stringify({ content })}\n\n`);
      } catch {}
    }
  }
  res.end();
});
```

```typescript
const RadarChart: React.FC<{ dimensions: ScoreDimension[]; size?: number }> = ({
  dimensions, size = 320,
}) => {
  const center = size / 2;
  const radius = size / 2 - 50;
  const angleStep = (Math.PI * 2) / dimensions.length;

  const dataPoints = dimensions.map((dim, index) => {
    const angle = index * angleStep - Math.PI / 2;
    const value = (dim.score / 100) * radius;
    return {
      x: center + Math.cos(angle) * value,
      y: center + Math.sin(angle) * value,
      labelX: center + Math.cos(angle) * (radius + 25),
      labelY: center + Math.sin(angle) * (radius + 25),
      label: dim.label, score: dim.score,
    };
  });

  const dataPolygon = dataPoints.map(p => `${p.x},${p.y}`).join(' ');

  return (
    <svg width={size} height={size}>
      {/* 网格圆 + 轴线 + 数据多边形 + 数据点标签 */}
      <polygon points={dataPolygon} fill="rgba(114,46,209,0.2)" stroke="#722ed1" strokeWidth="2" />
      {dataPoints.map((p, i) => (
        <g key={i}>
          <circle cx={p.x} cy={p.y} r="4" fill="#722ed1" />
          <text x={p.labelX} y={p.labelY} textAnchor="middle" fontSize="12">{p.label}</text>
          <text x={p.labelX} y={p.labelY + 14} textAnchor="middle" fill="#722ed1" fontSize="11" fontWeight="bold">{p.score}</text>
        </g>
      ))}
    </svg>
  );
};
```

```typescript
// src/services/ragService.ts

/**
 * RAG 流式问答流程：
 * 1. 检索知识库 → 2. 构建增强Prompt → 3. 调用AI流式生成
 */
export async function ragChatStream(
  messages: ZhipuMessage[],
  onChunk: (content: string) => void,
  options: { role: AIRole; systemPrompt: string; token?: string; enableRag?: boolean }
): Promise<{ sources: KnowledgeSnippet[] }> {
  const { systemPrompt, token, enableRag = true } = options;
  let snippets: KnowledgeSnippet[] = [];

  // 步骤1：检索知识库（取最后一条用户消息作为查询）
  const lastUserMessage = [...messages].reverse().find(m => m.role === 'user');
  if (enableRag && lastUserMessage) {
    snippets = await searchKnowledgeBase(lastUserMessage.content, 5);
  }

  // 步骤2：构建增强Prompt
  const enhancedPrompt = buildRagPrompt(systemPrompt, snippets, lastUserMessage?.content || '');

  // 步骤3：调用AI流式生成
  await chatWithZhipuStream(messages, onChunk, {
    system_prompt: enhancedPrompt, token,
  });

  return { sources: snippets };
}

/**
 * 构建RAG增强后的系统提示词
 */
export function buildRagPrompt(basePrompt: string, snippets: KnowledgeSnippet[], userQuestion: string): string {
  if (snippets.length === 0) return basePrompt;

  const knowledgeContext = snippets
    .map((s, i) => `【参考知识 ${i + 1}】（来源：${s.title}）\n${s.snippet}`)
    .join('\n\n---\n\n');

  return `${basePrompt}

【知识库参考信息】
以下是从知识库中检索到的相关资料，请优先参考这些信息回答用户问题。

${knowledgeContext}

【注意事项】
- 引用知识库内容时请注明来源
- 如果知识库信息不足，请基于自身能力回答并说明`;
}
```

```javascript
// JWT配置
const JWT_SECRET = process.env.JWT_SECRET || 'ai-mate-secret-key-change-in-production';
const JWT_EXPIRES_IN = '2h';
const REFRESH_EXPIRES_IN = '7d';

// 生成Token
function generateAccessToken(user) {
  return jwt.sign(
    { userId: user.id, username: user.username, role: user.role },
    JWT_SECRET,
    { expiresIn: JWT_EXPIRES_IN }
  );
}

// 认证中间件
function authMiddleware(req, res, next) {
  const token = extractToken(req);
  if (!token) {
    return res.status(401).json({ code: 401, message: '未提供认证令牌，请先登录' });
  }
  try {
    const decoded = jwt.verify(token, JWT_SECRET);
    req.user = { id: decoded.userId, username: decoded.username, role: decoded.role };
    next();
  } catch (err) {
    if (err.name === 'TokenExpiredError') {
      return res.status(401).json({ code: 401, message: '登录已过期', needRefresh: true });
    }
    return res.status(401).json({ code: 401, message: '认证失败' });
  }
}
```

```javascript
// 后端敏感词过滤中间件
const SENSITIVE_WORDS = ['违规词1', '违规词2', ...]; // 可从数据库或配置文件加载

function sensitiveWordFilter(text) {
  let filtered = text;
  SENSITIVE_WORDS.forEach(word => {
    const regex = new RegExp(word, 'gi');
    filtered = filtered.replace(regex, '*'.repeat(word.length));
  });
  return filtered;
}

// 在消息保存前过滤
app.post('/api/messages', async (req, res) => {
  const filteredContent = sensitiveWordFilter(req.body.content);
  // ... 保存过滤后的内容
});
```
