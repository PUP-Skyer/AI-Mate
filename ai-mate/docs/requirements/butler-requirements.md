# 管家模块功能需求文档（Butler Requirements）

> **文档版本：** v1.0
> **最后更新：** 2026-04-24
> **模块负责人：** 产品团队

---

## 1. 模块概述

### 1.1 模块定位

管家（Butler）是 AI Mate 平台的客户服务管家模块，定位为**客户服务管家**。该模块面向所有平台用户，提供智能 FAQ 查询、新手引导、问题反馈等全方位的用户支持服务，确保用户获得流畅、高效的使用体验。

### 1.2 核心价值

- **智能问答：** 通过分类和关键词检索，帮助用户快速找到常见问题的解答
- **新手引导：** 结构化的 6 步引导流程，帮助新用户快速上手平台核心功能
- **问题反馈：** 完善的反馈机制，支持 Bug 报告、功能建议、投诉等多种类型
- **闭环服务：** 反馈状态全流程跟踪，确保每个用户问题都有回应

### 1.3 目标用户

| 用户角色 | 典型场景 |
|----------|----------|
| 新注册用户 | 通过新手引导了解平台功能 |
| 普通用户 | 查询 FAQ 解决使用疑问 |
| 内容创作者 | 提交功能建议和 Bug 反馈 |
| 企业用户 | 提交售后问题和投诉 |
| 软件开发者 | 提交技术问题反馈、API 使用咨询 |
| AI 产品经理 | 咨询 AI 功能使用方法、提交产品改进建议 |
| 管理员 | 管理 FAQ 内容，处理用户反馈 |

## 2. 用户故事

### US-001：FAQ 关键词搜索

> 作为一名**普通用户**，我希望能够通过关键词搜索 FAQ，以便快速找到与我问题相关的解答。

**验收标准：**
- 支持在搜索框输入关键词
- 关键词匹配 question、answer 和 keywords 三个字段
- 搜索结果按相关度和排序权重排列
- 无结果时展示友好的提示信息

### US-002：FAQ 分类浏览

> 作为一名**普通用户**，我希望能够按分类浏览 FAQ 列表，以便在不确定关键词时也能找到相关信息。

**验收标准：**
- 支持按分类筛选（如：账户管理、功能使用、计费相关等）
- 仅展示状态为 ACTIVE 的 FAQ
- 列表按 sortOrder 降序、viewCount 降序排列
- 支持分页浏览

### US-003：FAQ 详情查看

> 作为一名**普通用户**，我希望能够查看 FAQ 的详细回答内容，以便获得完整的解决方案。

**验收标准：**
- 点击 FAQ 条目可查看完整的问题和回答
- 每次查看自动增加 viewCount
- 支持标记"有帮助"（helpfulCount +1）
- 回答内容支持富文本格式展示

### US-004：FAQ 内容管理（管理员）

> 作为一名**管理员**，我希望能够创建、编辑和删除 FAQ 内容，以便持续维护和更新帮助文档。

**验收标准：**
- 支持创建新 FAQ，填写问题、回答、分类、关键词和排序权重
- 支持编辑已有 FAQ 的所有字段
- 支持软删除 FAQ（不物理删除数据）
- 支持启用/停用 FAQ（ACTIVE/INACTIVE 状态切换）

### US-005：FAQ 排序管理（管理员）

> 作为一名**管理员**，我希望能够设置 FAQ 的排序权重，以便将重要和热门的 FAQ 展示在前面。

**验收标准：**
- 支持为每条 FAQ 设置 sortOrder 值
- 列表查询时按 sortOrder 降序排列
- sortOrder 值相同时按 viewCount 降序排列
- 支持批量调整排序权重

### US-006：新手引导流程

> 作为一名**新注册用户**，我希望能够通过结构化的引导流程快速了解平台功能，以便尽快上手使用。

**验收标准：**
- 首次登录自动触发引导流程
- 引导流程共 6 个步骤，按顺序进行
- 每完成一步自动记录进度
- 可以随时退出，下次登录继续未完成的步骤

### US-007：引导进度查看

> 作为一名**用户**，我希望能够查看自己的新手引导进度，以便了解还有哪些功能尚未了解。

**验收标准：**
- 能够查看当前引导状态（进行中、已完成、已跳过）
- 能够查看已完成的步骤列表
- 能够查看当前应进行的步骤编号
- 引导完成后展示完成提示

### US-008：跳过新手引导

> 作为一名**有经验的用户**，我希望能够跳过新手引导流程，以便直接开始使用平台。

**验收标准：**
- 在引导流程中提供"跳过引导"选项
- 跳过后引导状态变更为 SKIPPED
- 跳过后可在设置中重新开启引导
- 跳过操作需要二次确认

### US-009：提交 Bug 反馈

> 作为一名**内容创作者**，我希望能够提交 Bug 反馈并描述问题详情，以便技术团队及时修复问题。

**验收标准：**
- 反馈类型选择"Bug 报告"
- 必须填写反馈内容描述
- 可选填写联系方式
- 提交后状态默认为 PENDING
- 提交成功后展示确认提示

### US-010：提交功能建议

> 作为一名**内容创作者**，我希望能够提交功能改进建议，以便平台持续优化用户体验。

**验收标准：**
- 反馈类型选择"功能建议"
- 支持详细描述建议内容
- 可选填写联系方式以便后续沟通
- 提交后可在反馈列表中查看处理进度

### US-011：查看反馈处理进度

> 作为一名**用户**，我希望能够查看已提交反馈的处理状态和官方回复，以便了解问题的解决进展。

**验收标准：**
- 能够查看所有已提交的反馈列表
- 展示每条反馈的类型、内容、状态和提交时间
- 当有官方回复时，展示回复内容
- 支持分页浏览

### US-012：售后服务咨询

> 作为一名**企业用户**，我希望能够通过反馈系统提交售后服务问题，以便获得及时的技术支持。

**验收标准：**
- 反馈类型选择"投诉"或"其他"
- 支持填写详细的售后问题描述
- 支持填写联系方式（邮箱或手机号）
- 管理员可对反馈进行回复

## 5. 业务规则

### 5.1 FAQ 排序规则

FAQ 列表的排序遵循以下优先级规则：

| 优先级 | 排序字段 | 排序方向 | 说明 |
|--------|----------|----------|------|
| 1 | sortOrder | 降序（DESC） | 管理员设置的排序权重，值越大越靠前 |
| 2 | viewCount | 降序（DESC） | 当 sortOrder 相同时，按浏览量排序 |
| 3 | createdAt | 降序（DESC） | 当前两者均相同时，按创建时间排序 |

**详细规则：**

| 规则编号 | 规则名称 | 规则描述 |
|----------|----------|----------|
| FR-001 | 默认排序权重 | 新创建的 FAQ 默认 sortOrder = 0 |
| FR-002 | 仅展示启用项 | 列表查询仅返回 status = ACTIVE 的 FAQ |
| FR-003 | 浏览量自增 | 每次查看 FAQ 详情，viewCount 自动 +1 |
| FR-004 | 有帮助计数 | 用户点击"有帮助"按钮时，helpfulCount +1（同一用户对同一 FAQ 仅计一次） |
| FR-005 | 关键词格式 | keywords 字段多个关键词用英文逗号分隔 |
| FR-006 | 搜索范围 | 关键词搜索匹配 question、answer 和 keywords 三个字段 |

### 5.2 引导步骤定义

引导流程共 6 个步骤，用户需按顺序完成：

| 步骤编号 | 步骤名称 | 步骤描述 | 预计时长 |
|----------|----------|----------|----------|
| 1 | 欢迎介绍 | 了解 AI Mate 平台的核心功能定位和价值主张 | 1 分钟 |
| 2 | 创建账户 | 完善个人资料，设置行业偏好和创作方向 | 2 分钟 |
| 3 | 首次创作 | 在工匠模块创建第一条内容，体验基本创作流程 | 3 分钟 |
| 4 | AI 体验 | 体验 AI 辅助创作功能，了解如何利用 AI 提升效率 | 3 分钟 |
| 5 | 协作空间 | 了解团队协作功能，学习如何创建和管理协作空间 | 2 分钟 |
| 6 | 查看帮助 | 了解管家模块的 FAQ 和反馈功能，知道如何获取帮助 | 1 分钟 |

**引导规则：**

| 规则编号 | 规则名称 | 规则描述 |
|----------|----------|----------|
| GR-001 | 顺序完成 | 步骤必须按编号顺序完成，不可跳步 |
| GR-002 | 自动记录 | 每完成一步，自动将步骤编号加入 completedSteps 数组 |
| GR-003 | 进度更新 | currentStep 自动更新为已完成最后一步 + 1 |
| GR-004 | 完成判定 | 当 step = 6 完成后，status 自动变更为 COMPLETED |
| GR-005 | 不可重复 | 已完成的步骤不允许重复提交 |
| GR-006 | 终态限制 | 状态为 COMPLETED 或 SKIPPED 时，不可再完成步骤 |
| GR-007 | 唯一记录 | 每个用户仅有且仅有一条引导进度记录（userId 唯一约束） |
| GR-008 | 首次创建 | 用户首次查询引导进度时，若记录不存在则自动创建默认记录 |

### 5.3 反馈状态流转规则

用户反馈的状态遵循以下流转规则：

```
PENDING（待处理）──分配──> PROCESSING（处理中）──解决──> RESOLVED（已解决）──关闭──> CLOSED（已关闭）
```

**详细规则：**

| 当前状态 | 可变更为 | 触发条件 | 说明 |
|----------|----------|----------|------|
| PENDING | PROCESSING | 管理员分配处理人 | 反馈已被受理，开始处理 |
| PENDING | CLOSED | 管理员关闭 | 无效反馈或重复反馈，直接关闭 |
| PROCESSING | RESOLVED | 管理员标记已解决 | 问题已解决，需填写 reply |
| PROCESSING | PENDING | 管理员退回 | 处理人变更或需补充信息 |
| RESOLVED | CLOSED | 管理员关闭 | 确认用户满意后关闭 |
| RESOLVED | PROCESSING | 用户不满意 | 用户反馈未解决，重新处理 |
| CLOSED | - | - | 终态，不可变更 |

**注意事项：**
- 状态为 RESOLVED 或 CLOSED 时，reply 字段不能为空
- 状态变更时自动更新 updatedAt 时间戳
- 用户仅能查看自己提交的反馈，不能修改反馈状态
- 反馈状态变更可通过管理员后台操作，不在此接口文档范围内

## 6. 状态机

### 6.1 FAQ 状态机

```
     ┌──────────────┐         ┌──────────────┐
     │              │  停用    │              │
     │   ACTIVE     │ ──────> │  INACTIVE    │
     │  （启用）     │         │  （停用）     │
     │              │ <────── │              │
     └──────────────┘   启用  └──────────────┘

     注：ACTIVE 和 INACTIVE 可双向切换
     软删除的 FAQ 不在此状态机范围内
```

### 6.2 引导进度状态机

```
     ┌──────────────┐
     │              │
     │ IN_PROGRESS  │
     │  （进行中）   │
     │              │
     └──┬───────┬───┘
        │       │
        │       │ 跳过
        │       ▼
        │  ┌──────────────┐
        │  │              │
        │  │   SKIPPED    │
        │  │  （已跳过）   │
        │  │              │
        │  └──────────────┘
        │
        │ 完成全部步骤
        ▼
     ┌──────────────┐
     │              │
     │  COMPLETED   │
     │  （已完成）   │
     │              │
     └──────────────┘

     注：IN_PROGRESS、SKIPPED、COMPLETED 均为终态（不可回退）
         SKIPPED 和 COMPLETED 可通过管理员操作重新变更为 IN_PROGRESS
```

### 6.3 反馈状态机

```
                    ┌──────────────┐
                    │              │
         提交反馈    │   PENDING    │
        ──────────> │  （待处理）   │
                    │              │
                    └──┬───────┬───┘
                       │       │
                       │       │ 关闭（无效/重复）
                       │       ▼
                       │  ┌──────────────┐
                       │  │              │
                       │  │   CLOSED     │
                       │  │  （已关闭）   │
                       │  │              │
                       │  └──────────────┘
                       │
                       │ 分配处理人
                       ▼
                ┌──────────────┐
                │              │
                │ PROCESSING   │
                │  （处理中）   │
                │              │
                └──┬───────┬───┘
                   │       │
                   │       │ 退回
                   │       ▼
                   │  ┌──────────────┐
                   │  │              │
                   └──│   PENDING    │
                      │  （待处理）   │
                      └──────────────┘
                   │
                   │ 标记已解决（需填写 reply）
                   ▼
                ┌──────────────┐
                │              │
                │  RESOLVED    │
                │  （已解决）   │
                │              │
                └──┬───────┬───┘
                   │       │
                   │       │ 关闭
                   │       ▼
                   │  ┌──────────────┐
                   │  │              │
                   │  │   CLOSED     │
                   │  │  （已关闭）   │
                   │  │              │
```

| 存储服务 | 基础设施 | FAQ、引导进度和反馈的持久化存储 | P0 |
