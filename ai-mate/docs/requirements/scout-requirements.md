## 1. 模块概述

### 1.1 模块定位

探路者 (Scout) 是 AI Mate 平台的核心业务模块之一，定位为**投资商对接专家**。该模块致力于帮助创业者和企业高效对接优质投资商资源，提供从投资商发现、筛选、对比到行业趋势分析的全链路服务。

### 1.2 核心价值

- **精准匹配**: 基于投资偏好、行业赛道、区域等多维度信息，帮助用户快速锁定目标投资商
- **智能推荐**: 结合 AI 能力，为用户推荐最契合的投资合作伙伴
- **数据驱动**: 提供行业报告和市场行情分析，辅助用户做出更明智的融资决策
- **多维对比**: 支持投资商间的横向对比，直观呈现各投资商的优劣势

### 1.3 目标用户

| 角色 | 描述 |
|------|------|
| 创业者 | 寻求融资的初创企业创始人或融资负责人 |
| 企业融资负责人 | 成长期企业的CFO或融资总监 |
| 投资顾问 | 为企业提供融资咨询服务的专业顾问 |
| 软件开发者 | 寻求技术投资或项目孵化的独立开发者 |
| AI 产品经理 | 为 AI 产品寻找战略投资或合作机会的产品负责人 |
| 平台管理员 | 负责投资商数据维护和内容管理的运营人员 |

### 1.4 核心功能范围

| 功能域 | 说明 |
|--------|------|
| 投资商管理 | 投资商信息的增删改查及生命周期管理 |
| 智能搜索 | 基于关键词的多维度投资商搜索 |
| 对比分析 | 多投资商横向对比，辅助决策 |
| 行业报告 | 行业研究报告的浏览与查询 |
| AI 对话 | 通过 AI 通道获取投资商推荐和市场分析 |

## 2. 用户故事

### US-001 AI 智能推荐

> 作为一名创业者，我希望系统能根据我的项目描述和融资需求，智能推荐匹配的投资商，以便节省手动筛选的时间。

**验收标准**: 用户输入项目信息后，AI 返回 Top 5 推荐投资商列表，并给出匹配理由。

---

### US-002 行业报告查询

> 作为一名企业融资负责人，我希望能够浏览和搜索行业研究报告，以便了解当前市场趋势和投资热点。

**验收标准**: 支持按行业分类浏览报告，报告列表展示标题、摘要、发布日期等关键信息。

---

### US-003 市场行情分析

> 作为一名投资顾问，我希望能够获取特定行业的市场行情分析，以便为客户提供专业的融资市场洞察。

**验收标准**: AI 基于知识库中的行业报告生成市场分析摘要，包含融资规模、热门赛道、趋势预测等。

---

### US-004 报告详情与分享

> 作为一名投资顾问，我希望能够查看行业报告的完整内容并分享给客户，以便提供有价值的行业参考。

**验收标准**: 报告详情页展示完整正文，支持生成分享链接或导出为 PDF。

---

### US-005 投资商搜索

> 作为一名创业者，我希望能够通过关键词搜索投资商，以便快速找到与我所在行业相关的投资机构。

**验收标准**: 输入关键词后，系统能在名称、描述、资质中匹配相关投资商，并按相关度排序返回结果。

---

### US-006 分类筛选

> 作为一名企业融资负责人，我希望能够按投资类别（天使投资、VC、PE等）和区域筛选投资商，以便缩小目标范围，提高对接效率。

**验收标准**: 支持单选或多选类别和区域，筛选结果实时更新。

---

### US-007 投资商详情查看

> 作为一名创业者，我希望能够查看投资商的详细信息（投资偏好、管理规模、过往合作等），以便判断是否适合提交融资意向。

**验收标准**: 详情页展示投资商全部字段，包括评分、合作次数等动态数据。

---

### US-008 融资对接记录

> 作为一名创业者，我希望能够记录与投资商的对接历史（沟通时间、沟通内容、反馈结果），以便跟踪融资进展。

**验收标准**: 支持为每个投资商添加多条对接记录，按时间线展示。

---

### US-009 投资商对比

> 作为一名投资顾问，我希望能够同时选择多个投资商进行横向对比，以便为客户推荐最优的投资合作伙伴。

**验收标准**: 支持 2~5 个投资商对比，以表格或雷达图形式展示各维度差异。

---

### US-010 投资商收藏与管理

> 作为一名创业者，我希望能够收藏感兴趣的投资商并分组管理，以便在后续融资过程中快速查阅。

**验收标准**: 支持添加/移除收藏，支持自定义分组（如"已联系"、"待跟进"）。

---

### US-011 资源对比分析

> 作为一名创业者，我希望能够对比不同投资商的投资规模、评分和合作记录，以便选择最适合当前融资阶段的投资方。

**验收标准**: 对比页面清晰展示各投资商在关键指标上的差异，高亮最优项。

---

### US-012 投资商信息维护

> 作为一名平台管理员，我希望能够创建、编辑和删除投资商信息，以便保持平台数据的准确性和时效性。

**验收标准**: 管理员可通过后台界面完成投资商全生命周期管理，删除操作为软删除。

## 5. 业务规则

### 5.1 投资商评分规则

投资商综合评分（rating）取值范围为 **0.0 ~ 5.0**，评分由以下维度加权计算：

| 维度 | 权重 | 说明 |
|------|------|------|
| 合作完成度 | 30% | 历史合作项目的完成率和满意度 |
| 投资活跃度 | 25% | 近 12 个月的投资次数和金额 |
| 行业影响力 | 20% | 在目标行业中的知名度和口碑 |
| 响应及时性 | 15% | 对融资意向的平均响应时间 |
| 资质完备性 | 10% | 机构资质、备案信息的完备程度 |

**评分计算公式**:

```
rating = 合作完成度 * 0.30 + 投资活跃度 * 0.25 + 行业影响力 * 0.20 + 响应及时性 * 0.15 + 资质完备性 * 0.10
```

**评分更新规则**:
- 新创建的投资商默认评分为 `0.0`
- 评分每月计算更新一次
- 评分保留一位小数，采用四舍五入

### 5.2 对比算法

投资商对比基于以下维度进行：

| 维度 | 数据来源 | 比较方式 |
|------|----------|----------|
| 综合评分 | rating 字段 | 数值比较，取最大值 |
| 合作次数 | cooperationCount 字段 | 数值比较，取最大值 |
| 投资类别 | category 字段 | 分类展示，不比较优劣 |
| 所在区域 | region 字段 | 分类展示，不比较优劣 |
| 投资规模 | priceRange 字段 | 分类展示，不比较优劣 |

**对比规则**:
- 对比数量限制为 2~5 个投资商
- 数值型维度自动标记最优项（索引位置）
- 分类型维度仅做并列展示，不判定优劣
- 已删除（DELETED）的投资商不可参与对比

### 5.3 搜索排序逻辑

搜索结果排序采用**多级排序**策略：

1. **第一优先级 - 相关度评分**: 基于关键词匹配度计算相关度分数
   - 名称完全匹配：权重 3.0
   - 名称部分匹配：权重 2.0
   - 描述匹配：权重 1.5
   - 资质匹配：权重 1.0
2. **第二优先级 - 综合评分**: 相关度相同时，按 `rating` 降序排列
3. **第三优先级 - 合作次数**: 评分相同时，按 `cooperationCount` 降序排列
4. **第四优先级 - 创建时间**: 以上均相同时，按 `createdAt` 降序排列

**相关度计算示例**:

```
关键词: "人工智能"
- 名称包含"人工智能" → 相关度 += 3.0
- 描述包含"人工智能" → 相关度 += 1.5
- 资质包含"人工智能" → 相关度 += 1.0
```

### 5.4 投资商状态规则

| 规则 | 说明 |
|------|------|
| 新建默认状态 | 新创建的投资商默认状态为 `ACTIVE` |
| 列表可见性 | 仅 `ACTIVE` 状态的投资商出现在列表和搜索结果中 |
| 搜索可见性 | 仅 `ACTIVE` 状态的投资商可被搜索到 |
| 对比限制 | 仅 `ACTIVE` 状态的投资商可参与对比 |
| 更新限制 | `DELETED` 状态的投资商不可更新 |
| 重复删除 | 已删除的投资商再次删除返回 404 |

## 6. 状态机

### 6.1 投资商状态流转

投资商（Supplier）实体具有以下三种状态：

```
┌──────────┐         ┌───────────┐         ┌──────────┐
│  ACTIVE  │────────>│  INACTIVE │────────>│ DELETED  │
│  (活跃)   │         │  (停用)    │         │ (已删除)  │
└──────────┘         └───────────┘         └──────────┘
      │                                          │
      └──────────────────────────────────────────┘
                    (仅管理员操作)
```

### 6.2 状态定义

| 状态 | 值 | 说明 |
|------|----|------|
| 活跃 | ACTIVE | 投资商正常可用，可被搜索、列表展示和对比 |
| 停用 | INACTIVE | 投资商暂时停用，不可被搜索和列表展示，但数据保留 |
| 已删除 | DELETED | 投资商已被软删除，不可出现在任何查询结果中 |

### 6.3 状态流转规则

| 当前状态 | 目标状态 | 触发条件 | 操作权限 |
|----------|----------|----------|----------|
| ACTIVE | INACTIVE | 管理员手动停用 | 管理员 |
| ACTIVE | DELETED | 管理员执行删除操作 | 管理员 |
| INACTIVE | ACTIVE | 管理员重新激活 | 管理员 |
| INACTIVE | DELETED | 管理员执行删除操作 | 管理员 |
| DELETED | ACTIVE | 管理员恢复数据（后台操作） | 超级管理员 |

### 6.4 状态流转约束

- **ACTIVE -> INACTIVE**: 需确认该投资商无进行中的合作流程
- **INACTIVE -> ACTIVE**: 恢复前需验证投资商信息是否需要更新
- **任何状态 -> DELETED**: 软删除操作不可逆（通过常规接口），需超级管理员权限恢复
- **DELETED 状态**: 不可通过 PUT 接口更新，不可被搜索和列表查询，不可参与对比

## 7. 依赖关系

### 7.1 后端服务依赖

| 依赖组件 | 说明 | 接口/协议 |
|----------|------|-----------|
| ScoutController | 探路者模块核心控制器，提供投资商 CRUD、搜索、对比和报告查询的 RESTful API | Spring Boot REST API |
| serverless-proxy | AI 通道代理服务，负责将 AI 请求转发至大模型服务，用于投资商推荐和市场分析等智能功能 | HTTP / WebSocket |

### 7.2 AI 通道说明

探路者模块的 AI 智能功能（F-012、F-013、F-014）依赖 `serverless-proxy` 服务：

```
用户请求 → ScoutController → serverless-proxy → 大模型服务
```

**serverless-proxy 职责**:
- 接收前端或 ScoutController 发起的 AI 请求
- 进行请求格式转换和鉴权
- 转发至底层大模型服务（如 GPT、Claude 等）
- 将模型响应格式化后返回

**降级策略**:
- 当 serverless-proxy 不可用时，AI 相关功能应返回友好提示，不影响核心 CRUD 功能
- 搜索和对比功能不依赖 AI 服务，可独立运行

### 7.3 数据层依赖

| 依赖组件 | 说明 |
|----------|------|
| 数据库（MySQL/PostgreSQL） | 存储投资商信息、行业报告、用户收藏等结构化数据 |
| 知识库服务 | 存储行业报告正文和 AI 训练/检索所需的非结构化数据 |
| 缓存服务（Redis） | 缓存热门搜索结果、投资商评分等高频访问数据 |

### 7.4 外部依赖

| 依赖组件 | 说明 |
|----------|------|
| 认证服务 | 提供 Bearer Token 的签发和验证 |
