## 1. 角色定位

### 1.1 产品定位

军师 AI（Sage）是 AI Mate 平台中的**运营策略顾问**，专注于为创业者、企业管理者及运营团队提供数据驱动的运营策略规划与决策支持。Sage 将专业的商业分析方法论与 AI 生成能力深度融合，帮助用户从"拍脑袋决策"升级为"数据驱动决策"，大幅降低战略制定的专业门槛，让每个创业者都能拥有自己的"AI 军师"。

### 1.2 目标用户

| 用户类型 | 典型场景 | 核心诉求 |
|---------|---------|---------|
| **初创企业创始人** | 撰写商业计划书、制定运营策略 | 快速生成专业级策略文档，降低融资门槛 |
| **运营总监/经理** | 季度运营规划、营销方案制定 | 数据分析支撑、多方案对比、执行路径清晰 |
| **市场负责人** | 营销活动策划、增长策略制定 | 目标驱动的方案生成、ROI 预估 |
| **产品经理** | 产品增长策略、用户留存优化 | AARRR 漏斗分析、数据诊断与优化建议 |
| **中小企业主** | 经营诊断、竞争分析 | 低成本获取专业咨询级别的分析报告 |

### 1.3 核心价值

- **专业门槛降低**：将商业分析、策略制定等专业能力通过 AI 赋能给普通创业者，无需聘请昂贵的咨询顾问。
- **效率倍增**：传统需要数天甚至数周完成的策略文档，AI 辅助下可在数小时内完成初稿。
- **数据驱动决策**：内置多种分析框架（AARRR、SWOT、波特五力等），确保分析的系统性与科学性。
- **多方案对比**：为每个决策提供多个可选方案，附带优劣势分析与 ROI 预估，降低决策风险。
- **持续迭代优化**：支持文档版本管理与 AI 审阅，确保策略文档随业务发展持续更新。

### 1.4 与其他 AI 角色的协作关系

```
用户 → Scout（发现资源）→ Sage（制定策略）→ 执行落地
                              ↓
                    ┌─────────────────────┐
                    │  接收 Scout 数据     │
                    │  投资商分析结果       │
                    │  市场行情数据        │
                    │  行业报告摘要        │
                    └─────────┬───────────┘
                              │
                    ┌─────────▼───────────┐
                    │  生成策略文档        │
                    │  - 商业计划书 (BP)   │
                    │  - 运营方案          │
                    │  - 营销计划          │
                    │  - 增长策略          │
                    └─────────────────────┘
```

Sage 侧重于"分析"与"规划"，可接收来自 Scout 的资源分析数据作为策略制定的输入。同时，Sage 生成的策略文档中引用的市场数据也可反向请求 Scout 提供最新行情。

## 2. 核心功能

### 2.1 运营策略规划（BP 生成器）

#### 功能概述

提供基于模板的策略文档生成能力，用户选择文档类型与模板后，AI 根据用户提供的业务信息自动生成各章节内容，支持逐章生成、修改与 AI 审阅。

#### 支持的文档类型

| 文档类型 | 适用场景 | 核心章节 |
|---------|---------|---------|
| **商业计划书 (BP)** | 融资路演、创业规划 | 执行摘要、市场分析、产品方案、商业模式、团队介绍、财务预测、融资计划 |
| **运营规划书** | 季度/年度运营规划 | 运营现状分析、目标设定、策略制定、执行计划、资源配置、风险预案 |
| **营销策划案** | 营销活动、品牌推广 | 市场洞察、目标人群、创意策略、传播方案、预算分配、效果评估 |
| **竞品分析报告** | 市场竞争分析 | 竞品概览、产品对比、策略分析、SWOT 分析、应对策略 |

#### 模板机制

- **系统模板**：平台内置经过专业顾问审核的高质量模板，覆盖主流文档类型。
- **行业模板**：针对特定行业（如餐饮、电商、SaaS、制造业等）提供定制化模板。
- **自定义模板**：用户可基于已有文档保存为自定义模板，复用成功经验。
- **模板字段**：每个模板包含结构化的章节定义，每个章节有明确的写作指引与示例。

#### AI 生成能力

- **逐章生成**：用户可按章节逐一生成内容，每章独立编辑与确认。
- **上下文连贯**：AI 在生成后续章节时会参考已生成的内容，确保全文逻辑连贯。
- **数据引用**：AI 可引用 Scout 提供的市场数据、行业报告等内容，增强文档说服力。
- **风格适配**：支持选择文档风格（正式/简洁/生动），AI 自动调整语言风格。
- **图表生成**：AI 可根据数据自动生成配套图表（饼图、柱状图、流程图等）。

#### 文档管理

- **版本管理**：每次 AI 生成或用户编辑自动保存版本，支持版本对比与回滚。
- **协作编辑**：支持多人在线协作编辑，实时同步。
- **导出格式**：支持导出为 PDF、Word、Markdown 等格式。
- **分享与权限**：支持通过链接分享，可设置查看/编辑权限。

### 2.2 数据分析诊断

#### 功能概述

支持用户上传 CSV/Excel 格式的业务数据文件，AI 自动进行数据清洗、统计分析、异常检测与可视化，生成结构化的分析诊断报告。

#### 支持的数据类型

| 数据类型 | 典型字段 | 分析维度 |
|---------|---------|---------|
| **销售数据** | 日期、产品、销量、金额、渠道 | 销售趋势、产品排行、渠道分布 |
| **用户数据** | 注册时间、活跃度、付费情况 | 用户增长、留存率、付费转化 |
| **流量数据** | PV、UV、来源、页面、跳出率 | 流量趋势、来源分析、页面热力 |
| **财务数据** | 收入、成本、利润、现金流 | 财务健康度、成本结构、盈利趋势 |
| **客服数据** | 工单量、响应时间、满意度 | 服务效率、问题分类、满意度趋势 |

#### AI 分析流程

1. **数据解析**：自动识别文件编码、分隔符、数据类型，解析为结构化数据。
2. **数据质量评估**：检测缺失值、异常值、重复数据，生成数据质量报告。
3. **统计分析**：计算描述性统计量（均值、中位数、标准差、分位数等），识别数据分布特征。
4. **趋势分析**：对时间序列数据进行趋势识别、季节性分析、同比环比计算。
5. **异常检测**：基于统计方法与 AI 判断，识别数据中的异常点与异常模式。
6. **关联分析**：发现数据列之间的相关性，识别关键驱动因素。
7. **可视化生成**：自动选择合适的图表类型展示分析结果。
8. **诊断报告**：AI 综合以上分析生成自然语言诊断报告，包含关键发现、问题诊断与优化建议。

#### 交互方式

- **文件上传**：支持拖拽上传，文件大小限制 50MB，支持 .csv、.xlsx、.xls 格式。
- **对话式分析**：用户可在分析结果基础上继续提问，如"为什么 3 月份销量下降？"，AI 进行深入分析。
- **报告导出**：分析报告支持导出为 PDF 格式，包含图表与分析文本。

### 2.3 营销方案制定

#### 功能概述

基于用户设定的营销目标、预算范围与目标人群，AI 自动生成多套可选营销方案，每套方案包含策略概述、执行步骤、预算分配与 ROI 预估，支持方案间对比。

#### 方案生成输入

| 输入项 | 说明 | 示例 |
|-------|------|------|
| **营销目标** | 明确的营销目标 | "提升品牌知名度" / "获取新客户 1000 人" / "提升复购率 20%" |
| **目标人群** | 目标客户画像 | "25-35 岁一线城市白领，月收入 1-3 万" |
| **预算范围** | 营销预算 | "5-10 万元" / "10-20 万元/月" |
| **时间周期** | 方案执行周期 | "1 个月" / "一个季度" |
| **行业/产品** | 所在行业与产品信息 | "在线教育，K12 英语课程" |
| **渠道偏好** | 偏好的营销渠道（可选） | "优先考虑短视频和社交媒体" |

#### AI 生成输出

每套方案包含以下结构化内容：

```
营销方案
├── 方案名称与概述
├── 核心策略
│   ├── 品牌定位策略
│   ├── 内容策略
│   └── 渠道策略
├── 执行计划
│   ├── 第一阶段：预热期（第1周）
│   ├── 第二阶段：爆发期（第2-3周）
│   └── 第三阶段：长尾期（第4周）
├── 预算分配
│   ├── 渠道投放预算明细
│   ├── 内容制作预算
│   └── KOL/达人合作预算
├── KPI 设定
│   ├── 曝光量目标
│   ├── 点击率目标
│   ├── 转化率目标
│   └── ROI 目标
├── 风险评估
│   ├── 潜在风险点
│   └── 应对预案
└── 预期效果
    ├── 保守估计
    ├── 基准估计
    └── 乐观估计
```

#### 多方案对比

AI 默认生成 3 套差异化方案，用户可进行对比：

| 对比维度 | 方案 A（稳健型） | 方案 B（激进型） | 方案 C（创新型） |
|---------|---------------|---------------|---------------|
| 核心策略 | 搜索引擎投放为主 | 短视频信息流为主 | 社交裂变+KOL种草 |
| 预算分配 | 70%投放+30%内容 | 80%投放+20%内容 | 40%投放+40%KOL+20%内容 |
| 预期 ROI | 1:3 | 1:5（高风险） | 1:4（不确定性高） |
| 执行难度 | 低 | 中 | 高 |
| 适用场景 | 预算有限、求稳 | 追求快速增长 | 品牌建设+增长 |

### 2.4 增长策略建议

#### 功能概述

基于 AARRR（Acquisition 获取、Activation 激活、Retention 留存、Revenue 变现、Referral 传播）漏斗模型，对用户的业务增长进行全面诊断与策略建议。

#### AARRR 漏斗分析框架

```
        ┌─────────────┐
        │  Acquisition  │  获取：用户从哪里来？
        │   获客漏斗     │  - 渠道分析
        └──────┬──────┘  - 获客成本
               │         - 转化率
        ┌──────▼──────┐
        │  Activation   │  激活：用户是否体验到核心价值？
        │   激活漏斗     │  - 首次体验优化
        └──────┬──────┘  - Aha Moment 识别
               │         - 引导流程优化
        ┌──────▼──────┐
        │  Retention    │  留存：用户是否持续回来？
        │   留存漏斗     │  - 留存率分析
        └──────┬──────┘  - 流失预警
               │         - 召回策略
        ┌──────▼──────┐
        │  Revenue      │  变现：如何赚钱？
        │   变现漏斗     │  - ARPU 分析
        └──────┬──────┘  - 付费转化
               │         - LTV 计算
        ┌──────▼──────┐
        │  Referral     │  传播：用户是否愿意推荐？
        │   传播漏斗     │  - 裂变系数 K
        └─────────────┘  - 分享率分析
```

#### 分析输入

用户需提供以下信息（部分可由上传数据自动提取）：

- **业务类型**：如电商、SaaS、内容平台、社交应用等。
- **当前用户规模**：总用户数、月活用户数、日活用户数。
- **核心指标数据**：各阶段的转化率、留存率、ARPU、LTV 等（可手动输入或上传数据）。
- **当前痛点**：用户描述当前面临的主要增长瓶颈。

#### AI 分析输出

- **漏斗健康度评估**：对 AARRR 各阶段进行健康度评分（1-10 分），识别最薄弱环节。
- **瓶颈诊断**：针对评分最低的阶段进行深入分析，找出根本原因。
- **策略建议**：针对每个阶段提供 3-5 条可执行的增长策略建议，按优先级排序。
- **行业对标**：将用户的核心指标与行业平均水平进行对比，差距可视化展示。
- **行动路线图**：生成 30/60/90 天增长行动路线图，明确每阶段的关键任务与预期成果。

### 2.5 行业对标分析

#### 功能概述

支持用户选取竞争对手进行多维度对标分析，以结构化表格与可视化图表呈现差异，AI 给出竞争策略建议。

#### 对标维度

| 维度类别 | 具体指标 | 数据来源 |
|---------|---------|---------|
| **产品力** | 功能完整度、用户体验、创新性、技术壁垒 | 公开信息+AI分析 |
| **市场表现** | 市场份额、用户规模、增长率、品牌知名度 | 行业报告+公开数据 |
| **运营效率** | 获客成本、用户留存、付费转化、人效 | 估算+行业基准 |
| **财务健康** | 营收规模、盈利能力、融资情况 | 公开披露+估算 |
| **团队能力** | 团队规模、核心背景、组织能力 | 公开信息 |
| **渠道覆盖** | 销售渠道、合作伙伴、地域覆盖 | 公开信息+AI分析 |

#### AI 分析能力

- **SWOT 分析**：自动生成用户企业与竞争对手的 SWOT 分析矩阵。
- **差异化定位**：基于对标分析结果，AI 建议差异化竞争定位方向。
- **竞争策略建议**：针对每个竞争对手给出具体的竞争策略建议。
- **趋势预测**：基于当前竞争态势，预测未来 6-12 个月的竞争格局变化。

## 5. 数据模型

### 5.1 策略文档实体（StrategyDocument）

```typescript
interface StrategyDocument {
  id: string;                    // 主键，UUID 格式
  userId: string;                // 创建者用户 ID
  title: string;                 // 文档标题，最大长度 200
  type: DocumentType;            // 文档类型
  templateId: string;            // 使用的模板 ID
  content: string;               // 文档完整内容（富文本/Markdown）
  status: DocumentStatus;        // 文档状态
  version: number;               // 版本号，每次 AI 生成或审阅后递增
  businessInfo: {                // 业务信息快照
    companyName?: string;        // 企业名称
    industry?: string;           // 所属行业
    product?: string;            // 产品/服务描述
    targetMarket?: string;       // 目标市场
    coreAdvantage?: string;      // 核心优势
    currentStage?: string;       // 当前阶段
    teamSize?: string;           // 团队规模
    annualRevenue?: string;      // 年营收规模
  };
  createdAt: Date;               // 创建时间
  updatedAt: Date;               // 更新时间
}

enum DocumentType {
  BP = 'bp',                              // 商业计划书
  OPERATION_PLAN = 'operationPlan',       // 运营规划书
  MARKETING_PLAN = 'marketingPlan',       // 营销策划案
  COMPETITOR_ANALYSIS = 'competitorAnalysis' // 竞品分析报告
}

enum DocumentStatus {
  DRAFT = 'draft',             // 草稿
  GENERATING = 'generating',   // 生成中
  COMPLETED = 'completed',     // 已完成
  REVIEWED = 'reviewed'        // 已审阅
}
```

### 5.2 文档章节实体（DocumentSection）

```typescript
interface DocumentSection {
  id: string;                  // 主键，UUID 格式
  documentId: string;          // 所属文档 ID
  sectionKey: string;          // 章节标识，如 "executive_summary"
  title: string;               // 章节标题
  content: string | null;      // 章节内容（Markdown 格式），null 表示未生成
  aiGenerated: boolean;        // 是否为 AI 生成
  orderNum: number;            // 章节排序序号
  status: SectionStatus;       // 章节状态
  metadata: {                  // 附加元数据
    wordCount?: number;        // 字数统计
    charts?: ChartRef[];       // 引用的图表列表
    references?: Reference[];  // 引用的参考资料
    generationTime?: number;   // AI 生成耗时（毫秒）
    reviewScore?: number;      // 审阅评分
    reviewFeedback?: string;   // 审阅反馈
  };
  createdAt: Date;             // 创建时间
  updatedAt: Date;             // 更新时间
}

enum SectionStatus {
  PENDING = 'pending',         // 待生成
  GENERATING = 'generating',   // 生成中
  COMPLETED = 'completed',     // 已完成
  FAILED = 'failed'            // 生成失败
}

interface ChartRef {
  id: string;                  // 图表 ID
  type: 'bar' | 'line' | 'pie' | 'table' | 'flow';
  title: string;               // 图表标题
  dataUrl: string;             // 图表数据/图片 URL
}

interface Reference {
  source: string;              // 来源描述
  reportId?: string;           // 关联报告 ID（来自 Scout）
  title: string;               // 参考资料标题
  url?: string;                // 外部链接（可选）
}
```

### 6.3 关键技术方案

#### 6.3.1 文档生成实现

**生成策略**：

1. **大纲生成**：基于模板结构与用户业务信息，LLM 首先生成文档大纲，用户确认后进入逐章生成。
2. **逐章生成**：每个章节独立生成，携带完整的上下文信息（已生成章节摘要 + 业务信息 + 模板指引）。
3. **上下文管理**：采用"滑动窗口 + 摘要"策略，已生成章节通过 LLM 压缩为摘要，确保上下文不超限。
4. **流式输出**：采用 Server-Sent Events (SSE) 实现生成过程的实时流式展示，提升用户体验。
5. **图表生成**：AI 在生成文本时标注图表位置与数据，前端根据标注渲染 ECharts 图表。

**Prompt 工程要点**：

```
系统提示词结构：
├── 角色定义：你是一位资深商业顾问，擅长撰写[文档类型]
├── 写作规范：专业、数据驱动、逻辑清晰
├── 模板结构：[章节定义与写作指引]
├── 业务上下文：[用户提供的业务信息]
├── 已生成摘要：[前序章节的内容摘要]
├── 输出格式：Markdown 格式，图表用特殊标记标注
└── 约束条件：字数范围、禁止内容、引用规范
```

#### 6.3.2 数据分析实现

**Code Interpreter 方案**：

1. **数据解析**：服务端使用 Python（pandas）解析上传文件，识别列类型与数据特征。
2. **AI 代码生成**：LLM 根据数据特征与分析需求，生成 Python 分析代码。
3. **安全沙箱执行**：在 Docker 容器中执行生成的代码，限制网络访问与文件系统权限。
4. **结果收集**：收集代码执行输出（统计结果、图表图片、文本结论）。
5. **AI 报告生成**：LLM 基于分析结果生成自然语言诊断报告。

**安全措施**：
- 沙箱容器资源限制：CPU 1 核、内存 2GB、执行超时 60 秒。
- 禁止网络访问与文件写入。
- 代码静态检查：禁止 os、subprocess、shutil 等危险模块。
- 文件大小限制：最大 50MB，最大 100 万行。

#### 6.3.3 异步任务处理

**任务队列架构**：

```
用户请求 → API Server → Message Queue (Redis/RabbitMQ) → Worker Pool
                                                              │
                                                    ┌─────────┼─────────┐
                                                    │         │         │
                                                 Worker1   Worker2   Worker3
```

- **消息队列**：使用 Redis Stream 或 RabbitMQ 实现任务队列。
- **Worker 池**：根据 CPU 密集型任务动态扩缩容，默认 5 个 Worker。
- **进度推送**：Worker 通过 Redis Pub/Sub 发布进度，API Server 通过 WebSocket 推送给前端。
- **失败重试**：任务失败自动重试 3 次，间隔递增（5s/30s/120s）。
- **结果缓存**：分析结果缓存 24 小时，减少重复计算。

#### 6.3.4 文档版本管理

**版本策略**：
- 每次调用 AI 生成或 AI 审阅后自动创建新版本。
- 用户手动编辑后可选择是否创建版本。
- 保留最近 20 个版本，超出后自动归档。
- 版本间差异通过 diff 算法计算，支持可视化对比。

#### 6.3.5 性能要求

| 指标 | 目标值 |
|-----|--------|
| 单章节生成时间（P95） | < 15s |
| 全文审阅时间（P95） | < 30s |
| 数据分析任务完成时间 | < 60s（100万行以内） |
| 文档列表加载时间 | < 300ms |
| 系统可用性 | 99.9% |
| 并发文档生成支持 | 50 并发 |

### 6.4 安全与权限

- **数据隔离**：用户文档与分析结果严格隔离，不可跨用户访问。
- **文件安全**：上传文件病毒扫描，敏感数据自动脱敏（如身份证号、手机号）。
- **权限控制**：文档创建者拥有完整权限；协作者权限由创建者分配（查看/编辑/管理）。
- **频率限制**：文档生成限制每用户每小时 10 次；数据分析限制每用户每小时 3 次。
- **内容审核**：AI 生成内容经过敏感词过滤与合规检查，确保输出内容合法合规。
- **审计日志**：所有 AI 调用记录审计日志，包含输入摘要、输出摘要、Token 消耗、耗时等。

### 6.5 与 Scout 的集成方案

Sage 可通过内部 API 调用 Scout 的能力，获取数据支撑：

| 集成场景 | 调用方式 | 数据流向 |
|---------|---------|---------|
| 文档引用行业报告 | Sage → Scout `/api/scout/reports` | 获取报告摘要与关键数据 |
| 文档引用市场行情 | Sage → Scout 行情接口 | 获取最新市场趋势数据 |
| 竞品分析对标 | Sage → Scout `/api/scout/suppliers/search` | 获取竞争对手信息 |
| 策略引用资源对比 | Sage → Scout `/api/scout/compare` | 获取投资商对比结果 |

集成采用内部服务间调用（gRPC/HTTP），设置独立的调用配额与超时策略，避免 Scout 服务不可用时影响 Sage 核心功能。
